# W5 Evolution loop (proofread/store, proofread/evolve)

## Built
- `proofread/store/sqlite_store.py`: `SqliteStore(path)`, `SqliteEventLog(path)` (contracts.Store / EventLog).
  WAL, busy_timeout 60 s, `BEGIN IMMEDIATE` writes, safe for several processes on one file (tested with 4
  spawned writers). Docs table keyed (collection, id), JSON docs (MongoDB-shaped). Event log: AUTOINCREMENT
  seq (monotonic, never reused), UNIQUE idempotency key (re-append returns the original seq), append-only
  enforced by triggers, named cursors, extra `get_by_key`.
- `proofread/store/vector.py`: `embed(text) -> list[float]` and `NumpyVectorIndex(store=None, namespace=...)`.
  Persisted in store collection `vectors` (doc id `{namespace}:{doc_id}`), reloaded on construction.
- `proofread/store/mongo_store.py`: stubs with TODOs (change streams, Atlas Vector Search, counters for seq).
- `proofread/evolve/config.py`: `ArmConfig` (fields as specified plus defaults for bootstrap, screening,
  run_id, champion_mode, max_tasks) and `arm_preset("A"|"C"|"B"|"C-noret")`. `budget_key` = `arm_A`, `arm_C`,
  `arm_B`, `arm_C_noret`.
- `proofread/evolve/patching.py`: static gate. Editable-surface pointer check, W4 `apply_patch` when
  importable (else local jsonpatch + `Genome.model_validate` fallback), then own checks: tools only narrow,
  added_policies append-only with fresh non-base ids and compilable regexes, version untouched, size limits,
  no-op rejected, hide_tests arms keep `include_test_file_in_prompt=false`. `SURFACE_DESCRIPTION` is shown to the proposer.
- `proofread/evolve/proposer.py`: two model calls per edit. Step 1 intent from champion genome, per-task outcomes,
  truncated failure traces (from `trace_path`, missing tolerated), own history. Step 2 retrieves top-k similar
  rejected edits by intent embedding (skipped when `retrieval=False`) and asks for
  `{intent, patch, rationale}`. Objective stated as raising the pass fraction only; nothing about cheating.
- `proofread/evolve/stats.py`: paired bootstrap (numpy, seeded, 10,000 resamples), one-sided 80% lower bound;
  promote iff lb > 0 and delta >= 2 points. Pairs = (task_id, seed), workspace grader.
- `proofread/evolve/gates.py`: screening rule, formal gate (gated arms: any violation incl. FAILCLOSED rejects,
  counterfactual delta still recorded), empirical gate.
- `proofread/evolve/orchestrator.py`: `async run_arm(cfg, runner, proposer_client, store, eventlog, task_loader,
  deadline_ts=None, initial_genome=None)` plus CLI.

## Design decisions
- D-W5-1 Embedding: no embedding API among our keys. `embed` = feature hashing (blake2b) of word unigrams,
  word bigrams and char 3-grams into 512 dims with signed buckets, sublinear TF, L2 norm. Deterministic.
- D-W5-2 Screening rule: first 5 tasks of the (ordered) split, first seed. Reject (as rejected_empirical,
  reason "screening: ...") if candidate passes 0 while champion passed >= 3, or candidate passes >= 3 fewer.
  Screening episodes are reused by the full eval.
- D-W5-3 Champion re-evaluation each generation uses `champion_mode="observe"` (same as candidates) so the paired
  gate compares like with like. Enforce-mode champion runs belong to holdouts (W6/analysis).
- D-W5-4 Candidates per generation are proposed sequentially (each sees siblings in history), then evaluated
  concurrently. Among candidates passing all gates, the largest delta is promoted (ties: lowest index); others
  become rejected_empirical ("passed gates but a sibling candidate had a larger delta").
- D-W5-5 Runner exceptions other than BudgetExceeded count as a failed episode (error set) and are NOT persisted,
  so resume retries them. BudgetExceeded (runner or proposer) or the deadline stops the arm cleanly
  (`arm.stopped` event, summary `stopped` field); rerunning resumes.
- D-W5-6 Unparseable proposer output or failed static validation => status invalid (stored in edits and
  rejected_edits, indexed for retrieval).
- D-W5-7 New champion = candidate genome with version+1. Versions live in harness_versions as `{run_id}:v{n}`.

## Persistence layout (ids are deterministic; run_id defaults to `arm{name}`, e.g. `armC`)
- harness_versions `{run_id}:v{n}`: genome, genome_hash, generation, edit_id, parent, score.
- edits `{run_id}-g{gen}-c{k}`: intent, patch, rationale, retrieved, status, reason, delta_points, lb_points,
  counterfactual_delta_points, violations, candidate_rate, champion_rate, genome, proposer_cost_usd.
- rejected_edits: same doc for invalid / rejected_formal / rejected_empirical.
- episodes `{run_id}:g{gen}:{candidate_id|champion}:{task_id}:s{seed}`: EpisodeResult.model_dump + run_id.
- vectors `rejected:{run_id}:{edit_id}`.
- events keyed `{run_id}:{edit_id}:{proposed|screened|evaluated|decided|promoted}` and
  `{run_id}:g{gen}:{champion_evaluated|selection|done}`, `{run_id}:init`, `{run_id}:finished`.

## Run
```
uv run python -m proofread.evolve.orchestrator --arm C --db data/proofread.sqlite \
  --generations 3 --candidates 3 --model SLUG [--tasks N] [--seeds 0] [--concurrency 4] \
  [--deadline 2026-09-26T12:04:28Z] [--proposer-model claude-opus-5-5] [--trace-dir traces]
```
Wires W2 `list_tasks/load_task` (adapted to contracts.Task), W4 `make_episode_runner(trace_dir=...)` (which
resolves W1 sandbox, W3 verifier and graders itself) and W4 `make_client("proposer", model)`. Verified that the
real runner and proposer client construct (no API call made). Arms A and C can run as two processes on the same db.

## Tests
`uv run pytest tests/w5 -q` -> 33 passed (about 1.2 s). Covers: store CRUD/find/upsert, two connections, WAL,
4-process concurrent writers, event idempotency/monotonic seq/cursors/append-only; vector search + persistence;
bootstrap known cases and threshold; screening rule; formal vs ungated decision; static validation (accept and
10 reject cases, tools narrow, policies append-only, hide_tests, local fallback); orchestrator arm A promotes a
violating improvement while arm C rejects it as rejected_formal with counterfactual delta +70; multi-generation run
with screening, invalid and retrieval; C-noret; resume after a simulated crash matches the uninterrupted run with no
re-proposal and no rerun of persisted episodes; deadline; budget stop; runner exception handling.

## Contract change requests
- CR-W5-1 (for arm B): EpisodeRunner has no `hide_tests` parameter. Arm B currently only forces
  `context.include_test_file_in_prompt=false` in the genome. If B must truly hide test files from the workspace,
  add `hide_tests: bool = False` to EpisodeRunner.__call__ (W4) and the orchestrator will pass it.
