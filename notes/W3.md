## biject-api: NOT working (hard block, reason documented)
Full write-up: proofread/verify/BIJECT_INTERFACE.md. In short:
1. A locally built image exits at startup: its import-time .olean gate checks against an Ed25519
   public key hardcoded in biject-api's worker.py, so anything signed with a fresh local key fails
   (`SECURITY: olean signature check failed ...`). biject documents this as a known limitation.
   The CI-signed demo image (ghcr.io/bijectai/biject-api:<sha>) returns `unauthorized` on pull.
2. Even with a running service, biject's core invariant forbids free-form strings as kernel inputs
   (only enum/int/bool or hex64/oid_path/ident strings, max 104 bytes). Proofread policies must
   classify raw paths and raw source lines, so they cannot be expressed as biject policies without
   moving the classification out of Lean.
3. Mounting our Lean into biject would hit the same .olean gate; editing biject-api is not allowed.
Suggested BLOCKED.md entry for the integrator: "biject-api cannot host Proofread policies (olean
signature gate with hardcoded key + typed-input invariant). Fallback: ReferenceVerifier default;
LeanVerifier available as a formal cross-check."

project name proofread-biject; never the prod compose):

## Verifier kinds (proofread/verify/__init__.py)
`make_verifier(kind="auto", added_policies=None, net_allowlist=())`
- `auto`: BijectVerifier if `biject_available()` (health 200 AND registry holds a policy whose
  `source_hash` == reference.BASE_POLICY_HASH), else ReferenceVerifier. The check takes about 40 ms
  when biject is down.
- `reference`: ReferenceVerifier, source="reference", provisional=True, policy_hash read from
  reference.BASE_POLICY_HASH at construction.
- `lean`: LeanVerifier, source="lean", provisional=True (it is not biject-api). It runs the
  compiled `policycheck` executable (pool of persistent workers, chunking, timeouts, restart on
  death, cache). It fails closed if reference.BASE_POLICY_HASH differs from
  `lean_verifier.LEAN_SPEC_HASH` (the spec the Lean port was aligned to, currently 43854fa7...).
  That pin is only a drift guard for the Lean port: ReferenceVerifier and BijectVerifier read the
  hash at import time, as requested. If W1 changes reference.py again, the Lean port has to be
  re-aligned and the test `test_lean_port_aligned_to_current_reference` will flag it.
- `biject`: BijectVerifier (fails closed on every call while biject is down).
All kinds apply genome AddedPolicy rules via reference.evaluate_added on top of the base verdict.
Every failure path returns `Verdict(ok=False, failed_policies=["FAILCLOSED"], source="failclosed")`.

## Lean (proofread/policies/lean, every file marked DRAFT: PENDING HUMAN REVIEW)
- Proofread/Strings.lean: List Char helpers; `isWs` is exactly Python's `str.isspace` set.
- Proofread/Paths.lean: canon_path (posixpath.normpath semantics), protected-test and grader path
  classification, scope.
- Proofread/Markers.lean: one hand-written matcher per regex in reference.SKIP_PATTERNS (`\b`,
  `\s`, alternations, `.*` up to newline).
- Proofread/Policies.lean: `codeTest001` ... `codeAttr001 : Action -> Bool`, `failed`, Prop
  wrappers (`TestOk`, ..., `Compliant`) with Decidable instances.
- Proofread/Examples.lean: kernel-checked `by decide` examples.
- Main.lean: `policycheck` JSON-lines IO bridge (not policy logic).
- No sorry, native_decide, implemented_by, extern, partial, unsafe, or custom axioms in the policy
  files. `#print axioms` output is in proofread/policies/AXIOMS.txt: only propext,
  Classical.choice, Quot.sound.
- Build: `cd proofread/policies/lean && lake build` (toolchain v4.34.1, about 3 s). LeanVerifier
  builds the executable automatically if it is missing.
- PROVISIONAL / trusted bridge: Lean core has no Unicode tables, so the Python bridge
  (`lean_verifier.encode_action`) applies NFC to paths, the NFKC fold to added lines, `str.lower()`
  to hosts, and maps non-ASCII non-word characters in lines to U+0001. Every policy literal is
  ASCII, so this preserves all matches. All classification happens in Lean. Verdicts come from
  compiled Lean code, not from kernel checks.
